## 1. 목표 (1줄)
**창·카드를 키울 방법이 없던 문제**(사용자 요청 "맥 확대 안 되니?")를 풀기 위해
카드·글자·상태줄·창이 함께 커지는 **확대 배율 5단계**를 넣는다.

## 2. 범위
- **포함**
  1. **배율 5단계**: 100 · 125 · 150 · 175 · 200% — 메뉴 **보기 → 확대**, `Cmd+=` / `Cmd+-`, `Cmd+0`(100%)
  2. **저장·복원**: `settings["zoom"]`(전적 파일) — 다음 실행에도 유지. 옛 설정 파일(키 없음)은 100%로 정규화
  3. **화면 제한**: 창이 화면(가로 24px·세로 80px 여유)을 넘는 배율은 거절 + 상태줄 안내. 게임 전환으로 창이 넓어지면 **자동 축소**하고 안내(저장값은 유지 → 좁은 게임으로 돌아오면 복원)
  4. **그리기 구조**: 그리기·히트테스트·드래그·드롭 판정은 **1x 논리 좌표** 그대로. `redraw()` 끝에서 `zoom_items()`(canvas.scale + 선 두께), `update_fonts()`(글꼴)로만 배율 적용. `redraw()` 뒤에 만드는 항목(드롭 표시·힌트 테두리·우승 카드)은 만든 직후 같은 함수로 태그 확대, 마우스 좌표는 `logical()` 로 환산
  5. **검사**: UI 10건 추가 — 기본 100% / 150% 창·캔버스·카드 크기 / 150% 화면 좌표 끌어놓기 / 한 단계 축소 / 화면 밖 배율 거절 / 게임 전환 자동 축소 / 단축키 / 저장·복원
  6. 문서 갱신(CHANGELOG·TODO(T-007 분리)·README·DESIGN·api·AGENTS.local·본 PLAN) + 버전 v0.2.6(빌드 26)
- **제외**
  - **자유 창 크기 조절**(마우스로 늘리기) — 배율과 별개 과제로 T-007 에 남긴다(지금은 `resizable(False, False)` 유지)
  - 스위프트 네이티브 앱 확대 — 이번에는 파이썬 앱만(사용자 선택). 네이티브는 별도 과제
  - 카드 이동·뒤집기 소리, 승리 연출 다양화(T-007 나머지)

## 3. 설계 결정
| 결정 | 이유 |
|---|---|
| 그리기 좌표는 1x 그대로, **출력할 때만** `canvas.scale()` | 좌표를 배율로 미리 계산하면 카드 내부 여백(5·8·17px 등)까지 손봐야 하고 히트테스트·드래그·드롭 판정이 전부 배율을 알아야 한다. canvas.scale 은 좌표를 한 번에 키우고, 기존 검사(1x 좌표 비교)도 그대로 통과한다 |
| 글꼴은 `update_fonts()` 에서, 선 두께는 item 순회로 | `canvas.scale()` 은 글꼴 크기·선 두께를 키우지 않는다. 둘을 따로 처리해야 175%에서도 카드 글자가 카드에 맞는다 |
| 배율은 **화면에 들어갈 때만** 허용 | 창이 화면 밖으로 나가면 조작이 불가능하다. 200%는 이 화면(1800×1169)에서 높이 1148+여유가 넘어 거절되고 175%가 최대 |
| 게임 전환 시 자동 축소, 저장값은 유지 | 스파이더는 클론다이크보다 279px 넓다. 전환할 때마다 거절하면 불편하고, 저장값을 덮어쓰면 좁은 게임에 갔다 온 것만으로 취향 배율을 잃는다 |
| `Cmd+0` = 100% | 확대하다 원래 크기로 빨리 돌아오는 표준 단축키(macOS 문서 앱과 같은 관례) |
